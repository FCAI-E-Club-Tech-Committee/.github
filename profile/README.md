## 🗺️ Flagship Program: Scratch2Build Tech Academy (24 Weeks)

**Scratch2Build** is our flagship 24-week intensive technical academy where participants build, test, containerize, and deploy production-grade software live on public cloud infrastructure.

### The 24-Week 6-Milestone Roadmap

| Milestone | Weeks | Focus & Tech Stack | Major Deliverable / Capstone Output |
| :--- | :--- | :--- | :--- |
| **Milestone 1** | Weeks 1–4 | **Foundations & Product Framing**<br/>`HTML5`, `CSS3 (Flexbox/Grid)`, `ES6+ JS`, `Git/GitHub` | Interactive Portfolio & Portal Wireframe PR |
| **Milestone 2** | Weeks 5–8 | **Dynamic Full-Stack CRUD Core**<br/>`Node.js`, `Express.js`, `REST APIs`, `LocalStorage/JSON` | Full-Stack Activity Management CRUD App |
| **Milestone 3** | Weeks 9–12 | **Security, Auth & Data Persistence**<br/>`bcrypt`, `JWT`, `RBAC`, `PostgreSQL/Prisma`, `Multer` | Multi-User Portal with Auth, Roles & File Uploads |
| **Milestone 4** | Weeks 13–16 | **Component Architecture & Quality**<br/>`React.js`, `Next.js`, `Jest`, `Swagger/OpenAPI`, `OWASP` | Refactored, Tested, Documented & Hardened App |
| **Milestone 5** | Weeks 17–20 | **DevOps, Containerization & Observability**<br/>`Docker`, `GitHub Actions (CI/CD)`, `AWS/Render`, `Sentry` | Live Cloud-Hosted Deployed App with CI/CD |
| **Milestone 6** | Weeks 21–24 | **Capstone Sprints & Public Defense**<br/>`Production Product`, `Live Cloud URL`, `Technical Defense` | **Demo Day:** Public Defense before Technical Jury |

## ⚖️ Operational Policies & Governance

### 1. The 33% Guidance / 67% Hands-on Practice Rule
No session or workshop may spend more than **33%** of its duration on passive lecture or slides. At least **67%** of session time must be dedicated to live coding, active debugging, and code reviews.

### 2. Strict Hands-Off Mentoring Policy
Instructors and Pod Leads are **strictly prohibited from typing code on a student's keyboard**. Mentors guide participants using diagnostic questioning (*"What error status does Chrome DevTools display on line 24?"*).

### 3. The 4-Step Student Debugging Protocol
Before asking for help on Discord (`#office-hours`), students must execute 4 steps:
1. **Console:** Read terminal error messages and stack traces.
2. **Inspect:** Check DevTools / Network tab / variable states.
3. **Docs:** Search official documentation.
4. **Discord:** Post a structured bug report containing expected vs. actual results.

### 4. Code Review & PR Submission Rules
* **No Direct Commits:** Committing directly to `main` is disabled on all organization repositories. All work must occur on feature branches (`feature/your-full-name`).
* **PR Deadline:** Wednesdays at 11:59 PM.
* **Review SLA:** Pod Leads and Mentors must conduct line-by-line PR code reviews within **48 hours** of submission.

## 👥 Organizational Roles & Governance Hierarchy

1. **Tech Lead (All Committees):** Executive strategy, track health monitoring, and cross-functional policy enforcement.
2. **Department Heads (Web, Mobile, AI, etc.):** Track operational management, branch protection rules, PR SLAs, and weekly lab audits.
3. **Tech Instructors:** Content creation, slide/script design, and 120-minute Saturday Online Sync delivery.
4. **Tech Mentors (Pod Leads):** Small-group facilitation (Pods), hands-off lab guidance, and 48-hour GitHub PR reviews.
5. **HR & Operations:** Attendance logging, RAG Dashboard maintenance, 24-hour Yellow member outreach, and event logistics.
6. **Tech Team Members:** Committee developers building internal web platforms, starter repositories (`eclub_starter_task`), and automated tools.
7. **Tech Participants:** Enrolled students in Scratch2Build academies, workshops, and sprints.
